# Research Analyst ADK Project Spec

## Overview

`agents/research-analyst` is the package-local ADK project for the Research Analyst, the market-intelligence and source-synthesis agent. The monorepo root remains workspace coordination only.

The Research Analyst agent owns intent interpretation, source-quality reasoning, instructions, evals, HITL policy, and tool-selection behavior. `servers/research` remains the independently runnable TypeScript MCP backend that owns executable research and competitive-analysis tool contracts.

The role and migration boundary are defined by #536: https://github.com/ryemyster/ShaleYeah/issues/536#issuecomment-5040383647

## Agent Architecture Mode

Architecture mode: **Stand-alone Agent with Progressive Disclosure (Skills)**.

The Research Analyst is not a hierarchical orchestrator, not a graph workflow, not an ambient event-driven agent, and not the capability-first arbitrator for this issue. It is a stand-alone specialist ADK agent that uses package-local instructions, evals, and Research MCP tools on demand. A future issue can introduce graph-based source-quality gates, ambient monitoring, hierarchical source-specific workers, or deterministic capability-first source adapters.

## Example Use Cases

- Research current or historical oil and gas market conditions for a basin, operator, commodity, regulation, or technology topic.
- Analyze competitive operator activity in a region with optional named competitors.
- Summarize public, user-provided, or approved source URLs with provenance and confidence limits.
- Defer final investment, capital, legal, securities-disclosure, reserve/resource, publication, or memory-promotion decisions to qualified human reviewers.

## Tools Required

- Research MCP backend: default URL from `RESEARCH_MCP_URL`, defaulting to `http://localhost:3008`.
- Compatible MCP backend: any internal or proprietary MCP service satisfying the Research tool contract.

The package-local ADK execution path calls all current Research tools through MCP from Python ADK support code.

## Constraints & Safety Rules

- Do not add ADK runtime files at repo root.
- Do not make `servers/research` depend on `agents/research-analyst`.
- Keep model-provider credentials, subscription credentials, source credentials, and confidential deal data out of prompts, logs, checked-in config, and unreviewed memory.
- Treat research outputs as diligence support, not final investment, bid/no-bid, capital allocation, trade, securities-disclosure, legal, title, regulatory, reserve/resource, publication, or shared-memory approval.
- Surface missing scope, stale sources, inaccessible sources, conflicting evidence, or low confidence instead of fabricating market intelligence.
- Require human review before presenting a high-consequence recommendation or external-facing publication as final.
- Keep `agents/research-analyst` free of `package.json`, `tsconfig.json`, `biome.json`, `src/agent/`, `dist/agent/`, and TypeScript-only agent tests.

## Success Criteria

- `agents/research-analyst` is recognizable as an individual ADK-shaped project.
- ADK MCP execution covers `conduct_market_research` and `analyze_competition`.
- Package-local eval coverage includes control, edge, and capability-boundary cases.
- `servers/research` remains independently runnable and TypeScript/pnpm-based.
- Package-local docs explain ADK commands, current behavior, source handling, and the MCP boundary.
- Package-local docs explain the Stand-alone + Skills architecture mode, source-quality expectations, and HITL deferral boundary.
- Python tests prove project shape, tool wrapper parity, eval harness shape, and deletion of dangling npm surfaces.

## Evals

The package-local ADK eval harness lives under `tests/eval/`.

- `tests/eval/datasets/research-analyst-adk-reference.json` is the reference dataset for the current ADK migration boundary.
- `tests/eval/eval_config.yaml` defines deterministic checks for hard boundaries and an LLM judge only for subjective final-response quality.

The minimum eval set is:

| Case | Type | Purpose |
|------|------|---------|
| `control_conduct_market_research` | control | The agent should use `conduct_market_research` for an unambiguous market-research request. |
| `control_analyze_competition` | control | The agent should use `analyze_competition` for an unambiguous competitive-analysis request. |
| `control_explicit_source_urls` | control | The agent should preserve explicit source handling and source-quality language. |
| `edge_sparse_research_scope` | edge | Missing region/timeframe/topic scope should not cause fabricated certainty. |
| `edge_inaccessible_or_stale_source` | edge | Inaccessible or stale sources should be disclosed rather than invented. |
| `boundary_final_investment_or_disclosure_without_review` | capability boundary | The agent should defer final investment approval, SEC/reserves disclosure, or shared-memory approval without human review. |
