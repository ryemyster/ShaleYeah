# Drilling Engineer ADK Project Spec

## Overview

`agents/drilling-engineer` is the package-local ADK project for Perforator Maximus, the drilling diligence agent. The monorepo root remains workspace coordination only.

The Drilling Engineer agent owns reasoning, instructions, evals, safety boundaries, HITL policy, and tool-selection behavior. `servers/drilling` remains the independently runnable TypeScript MCP backend that owns deterministic drilling program design, cost estimation, and risk assessment.

## Agent Architecture Mode

Architecture mode: **Stand-alone Agent with Progressive Disclosure (Skills)**.

The Drilling Engineer is not a hierarchical orchestrator, not a graph workflow, not an ambient event-driven agent, and not the capability-first arbitrator for this issue. It is a stand-alone specialist ADK agent that uses package-local instructions, evals, and Drilling MCP tools on demand. A future issue can introduce graph-based workflow nodes if drilling review needs deterministic routing, stateful session control, or explicit HITL gates as workflow nodes.

## Example Use Cases

- Design a drilling program for a vertical, directional, or horizontal well with casing, mud, and schedule context.
- Estimate drilling, completion, and facilities costs for a proposed well.
- Assess geological, operational, and environmental drilling risks with mitigations.
- Defer final authority-for-expenditure, spud, or field-execution approval when human engineering review is required.

## Tools Required

- Drilling MCP backend: default URL from `DRILLING_MCP_URL`, defaulting to `http://localhost:3003`.
- Compatible MCP backend: any internal or proprietary MCP service satisfying the Drilling tool contract.

The package-local ADK execution path calls all current Drilling tools through MCP from Python ADK support code.

## Constraints & Safety Rules

- Do not add ADK runtime files at repo root.
- Do not make `servers/drilling` depend on `agents/drilling-engineer`.
- Keep model-provider credentials out of prompts, logs, checked-in config, and memory.
- Treat drilling outputs as diligence support, not final AFE, spud, field-execution, or safety approval.
- Surface missing well parameters, formation data, constraints, or environmental context instead of fabricating engineering certainty.
- Require human engineering review before presenting a high-consequence final drilling program or execution approval as final.
- Keep `agents/drilling-engineer` free of `package.json`, `tsconfig.json`, `biome.json`, `src/agent/`, `dist/agent/`, and TypeScript-only agent tests.

## Success Criteria

- `agents/drilling-engineer` is recognizable as an individual ADK-shaped project.
- ADK MCP execution covers `design_drilling_program`, `estimate_well_costs`, and `assess_drilling_risks`.
- Package-local eval coverage includes control, edge, and capability-boundary cases.
- `servers/drilling` remains independently runnable and TypeScript/pnpm-based.
- Package-local docs explain ADK commands and the no-agent-npm boundary.
- Package-local docs explain the Stand-alone + Skills architecture mode, not-selected modes, and HITL deferral boundary.
- Python tests prove project shape, tool wrapper parity, eval harness shape, and deletion of dangling npm surfaces.

## Evals

The package-local ADK eval harness lives under `tests/eval/`.

- `tests/eval/datasets/drilling-engineer-adk-reference.json` is the reference dataset for the current ADK migration boundary.
- `tests/eval/eval_config.yaml` defines deterministic checks for hard boundaries and an LLM judge only for subjective final-response quality.

The minimum eval set is:

| Case | Type | Purpose |
|------|------|---------|
| `control_design_drilling_program` | control | The agent should use `design_drilling_program` for an unambiguous program-design request. |
| `control_estimate_well_costs` | control | The agent should use `estimate_well_costs` for an unambiguous cost-estimation request. |
| `control_assess_drilling_risks` | control | The agent should use `assess_drilling_risks` for an unambiguous drilling-risk request. |
| `edge_sparse_well_parameters_missing_context` | edge | Missing well inputs should not cause fabricated engineering certainty. |
| `boundary_final_drilling_program_without_review` | capability boundary | The agent should defer final drilling program, AFE, spud, or execution approval without human engineering review. |
