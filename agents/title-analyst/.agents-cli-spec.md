# Title Analyst ADK Project Spec

## Overview

`agents/title-analyst` is the package-local ADK project for Titulus Verificatus, the oil and gas title diligence agent. The monorepo root remains workspace coordination only.

The Title Analyst agent owns reasoning, instructions, evals, safety boundaries, and tool-selection behavior. `servers/title` remains the independently runnable TypeScript MCP backend that owns title examination, lease analysis, burden checks, and chain-of-title processing.

## Example Use Cases

- Examine working interest and net revenue interest for a tract.
- Analyze lease term, expiry, depth severance, and acreage limitations.
- Identify ORRI, production payments, liens, and other encumbrances.
- Trace chain of title and list curative requirements.
- Defer legal-signoff language when title defects require attorney or landman review.

## Tools Required

- Title MCP backend: default URL from `TITLE_MCP_URL`, defaulting to `http://localhost:3010`.
- Compatible MCP backend: any internal or proprietary MCP service satisfying the title tool contract.

The package-local ADK execution path calls all current Title tools through MCP from Python ADK support code.

## Constraints & Safety Rules

- Do not add ADK runtime files at repo root.
- Do not make `servers/title` depend on `agents/title-analyst`.
- Keep model-provider credentials out of prompts, logs, checked-in config, and memory.
- Treat title outputs as diligence support, not final legal opinion.
- Surface missing documents, jurisdiction, legal description, tract identifiers, and curative gaps instead of fabricating title certainty.
- Require human legal/land review before presenting title as final, clean, or approved.
- Keep `agents/title-analyst` free of `package.json`, `tsconfig.json`, `biome.json`, `src/agent/`, and TypeScript-only agent tests.

## Success Criteria

- `agents/title-analyst` is recognizable as an individual ADK-shaped project.
- ADK MCP execution covers `examine_ownership`, `analyze_lease`, `check_burdens`, and `trace_chain_of_title`.
- Package-local eval coverage includes control, edge, and capability-boundary cases.
- `servers/title` remains independently runnable and TypeScript/pnpm-based.
- Package-local docs explain ADK commands and the no-agent-npm boundary.
- Python tests prove project shape, tool wrapper parity, eval harness shape, and deletion of dangling npm surfaces.

## Evals

The package-local ADK eval harness lives under `tests/eval/`.

- `tests/eval/datasets/title-analyst-adk-reference.json` is the reference dataset for the current ADK migration boundary.
- `tests/eval/eval_config.yaml` defines deterministic checks for hard boundaries and an LLM judge only for subjective final-response quality.

The minimum eval set is:

| Case | Type | Purpose |
|------|------|---------|
| `control_examine_ownership` | control | The agent should use `examine_title_ownership` for an unambiguous WI/NRI request. |
| `control_analyze_lease` | control | The agent should use `analyze_title_lease` for an unambiguous lease-term request. |
| `control_check_burdens` | control | The agent should use `check_title_burdens` for an unambiguous encumbrance request. |
| `control_trace_chain_of_title` | control | The agent should use `trace_title_chain_of_title` for an unambiguous chain request. |
| `edge_missing_legal_description` | edge | Missing legal description or tract id should not cause fabricated title certainty. |
| `boundary_final_clean_title_without_review` | capability boundary | The agent should defer final clean-title/legal-opinion language without human review. |
