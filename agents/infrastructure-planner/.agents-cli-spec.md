# Infrastructure Planner ADK Project Spec

## Overview

`agents/infrastructure-planner` is the package-local ADK project for the Infrastructure Planner, the surface and midstream feasibility agent for oil and gas diligence. The monorepo root remains workspace coordination only.

The Infrastructure Planner agent owns intent interpretation, tool selection, instructions, evals, HITL policy, memory-promotion policy, missing-input handling, confidence language, and user-facing synthesis. `servers/infrastructure` remains the independently runnable TypeScript MCP backend that owns executable tool contracts for pipeline planning, facility sizing, CAPEX estimation, and compliance assessment.

The role and migration boundary are defined by #544: https://github.com/ryemyster/ShaleYeah/issues/544#issuecomment-5040570094

## Agent Architecture Mode

Architecture mode: **Stand-alone Agent with Progressive Disclosure (Skills)**.

The Infrastructure Planner is not a hierarchical orchestrator, not a graph workflow, not an ambient event-driven agent, and not the capability-first arbitrator for this issue. It is a stand-alone specialist ADK agent that uses package-local instructions, evals, and Infrastructure MCP tools on demand. A future issue can introduce graph-based stage gates, ambient capacity or permit monitoring, hierarchical pipeline/facilities/water/power/regulatory workers, or deterministic capability-first GIS/capacity adapters.

## Example Use Cases

- Plan gathering or pipeline infrastructure for a proposed well program.
- Size batteries, separators, compressors, and saltwater-disposal capacity for expected production.
- Estimate infrastructure CAPEX with transparent assumptions.
- Assess likely permitting, pipeline-safety, disposal, environmental, and right-of-way review needs.
- Defer final engineering, construction, route, regulatory, legal/right-of-way, commercial, public-disclosure, and sensitive memory-promotion decisions to qualified human reviewers.

## Tools Required

- Infrastructure MCP backend: default URL from `INFRASTRUCTURE_MCP_URL`, defaulting to `http://localhost:3012`.
- Compatible MCP backend: any internal or proprietary MCP service satisfying the Infrastructure tool contract.

The package-local ADK execution path calls all current Infrastructure tools through MCP from Python ADK support code.

## Constraints & Safety Rules

- Do not add ADK runtime files at repo root.
- Do not make `servers/infrastructure` depend on `agents/infrastructure-planner`.
- Keep asset locations, development plans, midstream terms, ROW/easement details, operator designs, environmental studies, proprietary capacity data, and secrets out of prompts, logs, checked-in config, and unreviewed memory.
- Treat public GIS/map data as planning context, not survey-grade truth.
- Treat outputs as diligence support, not final pipeline route approval, facility layout approval, construction authorization, AFE/capital/procurement authorization, ROW/easement decision, midstream commitment, permit certification, PHMSA compliance certification, UIC/Class II approval, environmental conclusion, public disclosure, or shared-memory approval.
- Surface missing location, well count, production, phasing, facility, water, ROW, environmental, regulatory, commercial, and data-vintage inputs instead of fabricating infrastructure certainty.
- Require human review before high-consequence approvals, external commitments, final certifications, or sensitive memory promotion.
- Keep `agents/infrastructure-planner` free of `package.json`, `tsconfig.json`, `biome.json`, `src/agent/`, `dist/agent/`, and TypeScript-only agent tests.

## Success Criteria

- `agents/infrastructure-planner` is recognizable as an individual ADK-shaped project.
- ADK MCP execution covers `plan_pipeline`, `size_facilities`, `estimate_costs`, and `assess_compliance`.
- Package-local eval coverage includes control, edge, and capability-boundary cases.
- `servers/infrastructure` remains independently runnable and TypeScript/pnpm-based.
- Package-local docs explain ADK commands, current behavior, data-source limits, and the MCP boundary.
- Package-local docs explain the Stand-alone + Skills architecture mode and role-specific HITL deferral boundary.
- Python tests prove project shape, tool wrapper parity, eval harness shape, and deletion of dangling npm surfaces.

## Evals

The package-local ADK eval harness lives under `tests/eval/`.

- `tests/eval/datasets/infrastructure-planner-adk-reference.json` is the reference dataset for the current ADK migration boundary.
- `tests/eval/eval_config.yaml` defines deterministic checks for hard boundaries and an LLM judge only for subjective final-response quality.

The minimum eval set is:

| Case | Type | Purpose |
|------|------|---------|
| `control_plan_pipeline` | control | The agent should use `plan_pipeline` for an unambiguous pipeline/gathering request. |
| `control_size_facilities` | control | The agent should use `size_facilities` for an unambiguous facility-sizing request. |
| `control_estimate_costs` | control | The agent should use `estimate_costs` for an unambiguous infrastructure CAPEX request. |
| `control_assess_compliance` | control | The agent should use `assess_compliance` for permitting, safety, environmental, or compliance review. |
| `edge_sparse_infrastructure_scope` | edge | Missing location, well count, and production should not cause fabricated certainty. |
| `edge_public_gis_or_remote_route_uncertainty` | edge | Public GIS, federal/remote-route, and data-vintage limits should be disclosed. |
| `edge_disposal_or_conflicting_phasing_inputs` | edge | Produced-water disposal gaps and conflicting development assumptions should be separated. |
| `boundary_no_unreviewed_approval_or_certification` | capability boundary | The agent should defer final approvals, certifications, commitments, and sensitive memory promotion. |
