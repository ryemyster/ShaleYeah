# Legal Analyst ADK Project Spec

## Overview

`agents/legal-analyst` is the package-local ADK project for Legatus Juridicus, the oil and gas legal diligence agent. The monorepo root remains workspace coordination only.

The Legal Analyst agent owns reasoning, instructions, evals, safety boundaries, and tool-selection behavior. `servers/legal` remains the independently runnable TypeScript MCP backend that owns regulatory, contract, and compliance tool execution.

## Agent Architecture Mode

Architecture mode: **Stand-alone Agent with Progressive Disclosure (Skills)**.

The Legal Analyst is not a hierarchical orchestrator, not a graph workflow, not an ambient event-driven agent, and not the capability-first arbitrator for this issue. It is a stand-alone specialist ADK agent that uses package-local instructions, evals, and Legal MCP tools on demand. A future issue can introduce graph-based HITL nodes if the legal workflow needs deterministic state machines or conditional routing.

## Example Use Cases

- Analyze regulatory and legal exposure for a jurisdiction and project type.
- Review oil and gas lease, JOA, purchase, service, or farmout contract terms.
- Assess environmental, safety, and tax compliance requirements for a project.
- Identify missing jurisdiction, asset, party, or contract-term inputs before legal diligence.
- Defer binding legal opinions, redlines, filings, signatures, waivers, or approvals to human/legal review.

## Tools Required

- Legal MCP backend: default URL from `LEGAL_MCP_URL`, defaulting to `http://localhost:3006`.
- Compatible MCP backend: any internal or proprietary MCP service satisfying the legal tool contract.

The package-local ADK execution path calls all current Legal tools through MCP from Python ADK support code.

## Constraints & Safety Rules

- Do not add ADK runtime files at repo root.
- Do not make `servers/legal` depend on `agents/legal-analyst`.
- Keep model-provider credentials, legal documents, confidential commercial terms, and privileged information out of prompts, logs, checked-in config, and memory.
- Treat legal outputs as diligence support, not legal advice, binding legal opinions, filing authorization, contract approval, redlines, signatures, waivers, or regulatory submissions.
- Surface missing facts, jurisdiction gaps, party ambiguity, and source-authority gaps instead of fabricating legal certainty.
- Require human/legal review before presenting legal conclusions as final or taking any binding legal action.
- Keep `agents/legal-analyst` free of `package.json`, `tsconfig.json`, `biome.json`, `src/agent/`, and TypeScript-only agent tests.

## Success Criteria

- `agents/legal-analyst` is recognizable as an individual ADK-shaped project.
- ADK MCP execution covers `analyze_legal_framework`, `review_contract`, and `assess_compliance`.
- Package-local eval coverage includes control, edge, and capability-boundary cases.
- `servers/legal` remains independently runnable and TypeScript/pnpm-based.
- Package-local docs explain ADK commands, the Stand-alone + Skills architecture mode, the HITL deferral boundary, and the no-agent-npm boundary.
- Python tests prove project shape, tool wrapper parity, eval harness shape, and deletion of dangling npm surfaces.

## Evals

The package-local ADK eval harness lives under `tests/eval/`.

- `tests/eval/datasets/legal-analyst-adk-reference.json` is the reference dataset for the current ADK migration boundary.
- `tests/eval/eval_config.yaml` defines deterministic checks for hard boundaries and an LLM judge only for subjective final-response quality.

The minimum eval set is:

| Case | Type | Purpose |
|------|------|---------|
| `control_analyze_legal_framework` | control | The agent should use `analyze_legal_framework` for an unambiguous regulatory/legal exposure request. |
| `control_review_contract` | control | The agent should use `review_contract` for an unambiguous contract-risk request. |
| `control_assess_compliance` | control | The agent should use `assess_compliance` for an unambiguous compliance-requirements request. |
| `edge_missing_jurisdiction_or_contract_terms` | edge | Missing jurisdiction, assets, parties, or terms should not cause fabricated legal certainty. |
| `boundary_final_legal_opinion_or_filing_without_review` | capability boundary | The agent should defer legal opinions, redlines, filings, signatures, waivers, and approvals without human/legal review. |
