# Market Analyst ADK Project Spec

## Overview

`agents/market-analyst` is the package-local ADK project for Mercatus Analyticus, the oil and gas market intelligence agent. The monorepo root remains workspace coordination only.

The Market Analyst agent owns reasoning, instructions, evals, safety boundaries, and tool-selection behavior. `servers/market` remains the independently runnable TypeScript MCP backend that owns market-condition and competitive-landscape processing.

## Agent Architecture Mode

Architecture mode: **Stand-alone Agent with Progressive Disclosure (Skills)**.

The Market Analyst is not a hierarchical orchestrator, not a graph workflow, not an ambient event-driven agent, and not the capability-first arbitrator for this issue. It is a stand-alone specialist ADK agent that uses package-local instructions, evals, and Market MCP tools on demand. A future issue can introduce graph-based workflow nodes if market review needs deterministic routing, stateful session control, or explicit HITL gates as workflow nodes.

## Example Use Cases

- Analyze oil, gas, or combined commodity market conditions for a basin or region.
- Assess competitive landscape for an asset, basin, formation, or market.
- Explain when live EIA data is unavailable and the backend fell back to documented stub prices.
- Defer unsupported deal-price, bid, or investment recommendations when market data is incomplete.

## Tools Required

- Market MCP backend: default URL from `MARKET_MCP_URL`, defaulting to `http://localhost:3007`.
- Compatible MCP backend: any internal or proprietary MCP service satisfying the market tool contract.

The package-local ADK execution path calls all current Market tools through MCP from Python ADK support code.

## Constraints & Safety Rules

- Do not add ADK runtime files at repo root.
- Do not make `servers/market` depend on `agents/market-analyst`.
- Keep model-provider credentials and EIA keys out of prompts, logs, checked-in config, and memory.
- Treat market outputs as diligence support, not final bid, pricing, or investment approval.
- Surface stale, missing, or stubbed market data instead of fabricating live-market certainty.
- Require human review before presenting high-consequence bid, acquisition, or investment recommendations as final.
- Keep `agents/market-analyst` free of `package.json`, `tsconfig.json`, `biome.json`, `src/agent/`, and TypeScript-only agent tests.

## Success Criteria

- `agents/market-analyst` is recognizable as an individual ADK-shaped project.
- ADK MCP execution covers `analyze_market_conditions` and `competitive_analysis`.
- Package-local eval coverage includes control, edge, and capability-boundary cases.
- `servers/market` remains independently runnable and TypeScript/pnpm-based.
- Package-local docs explain ADK commands and the no-agent-npm boundary.
- Package-local docs explain the Stand-alone + Skills architecture mode, not-selected modes, and HITL deferral boundary.
- Python tests prove project shape, tool wrapper parity, eval harness shape, and deletion of dangling npm surfaces.

## Evals

The package-local ADK eval harness lives under `tests/eval/`.

- `tests/eval/datasets/market-analyst-adk-reference.json` is the reference dataset for the current ADK migration boundary.
- `tests/eval/eval_config.yaml` defines deterministic checks for hard boundaries and an LLM judge only for subjective final-response quality.

The minimum eval set is:

| Case | Type | Purpose |
|------|------|---------|
| `control_analyze_market_conditions` | control | The agent should use `analyze_market_conditions` for an unambiguous commodity-market request. |
| `control_competitive_analysis` | control | The agent should use `competitive_analysis` for an unambiguous competitive-landscape request. |
| `edge_missing_region_or_data_source` | edge | Missing region or stale/stubbed data should not cause fabricated market certainty. |
| `boundary_final_bid_recommendation_without_review` | capability boundary | The agent should defer final bid/investment recommendation language without human review. |
