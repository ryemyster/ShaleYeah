# Evaluate QA as an employee

QA's job score is separate from the input data's score. Correctly identifying a
critical failed check is a successful employee output; changing it to `PASS` is
a failure. The editable performance profile selects installed deterministic metrics,
thresholds and case-to-tool expectations. The separate data-rule profile decides
which observed assertions the backend runs.

The seven starter cases cover observed pass/zero, retained critical failure,
missing reference, changed revision, self-waiver, an exception that does not
repair data, and confidential-source access. Negative cases deliberately contain
an unsafe output or dispatch; their expected blocked verdicts and required failed
metrics are data in the dataset. Qualification checks all three case families
and the unchanged baseline. An optional judge can grade prose under an approved
rubric but cannot override trusted schema, provenance or human-authority gates.

Labels were authored and reviewed provisionally by Codex using the primary-source
research in the [role charter](ROLE.md), the accepted eight-dimensional observed
rule profile, and the repository's exact review/source contracts. The frozen
observed report fixtures were generated by the real QA service from synthetic
zero-valued data and configured units failure, missing-reference and malformed-data cases on 2026-10-13. Fixture
source bytes, profile rules, actual defect locations, counts and result references
are retained. Profile and dataset SHA-256 hashes bind each score. The installed
registry records metric versions and evaluation results record runtime, harness,
model and code revisions.

The primary research basis includes [PPDM data quality](https://ppdm.org/ppdm/PPDM/Collaboration/Committees/Rules_WG/PPDM/Data_Rules.aspx),
[Energistics standards](https://energistics.org/the-standards), and
[GX Core 1.24.0 validation workflows](https://docs.greatexpectations.io/docs/core/introduction/gx_overview/).
These define useful checks and input considerations; no licensed PPDM rule library,
expert truth set or live connector is claimed. See the charter's source/access
limitations before applying starter severity labels to operator data.

The fixture policy identifies `fixture.codex-research-review`, not a credentialed
professional reviewer. Metadata always says `professionalAcceptance: false`.
There is no measured 80% field-accuracy claim or measured human-effort saving.
Operators and open-source contributors can refine rule relevance, materiality,
labels and provider performance through versioned profiles and datasets. Final
MVP human workflow acceptance remains a separate release requirement.

The Energistics overview and GX Core 1.24.0 guide were refreshed on 2026-10-13.
PPDM timed out on that refresh; its prior charter research and entitlement limits
remain the cited basis, without a claim of newly retrieved rule content.

Regenerate the authored source packets by running
`node --import tsx tests/fixtures/freeze-employee.ts OUTPUT_JSON` from
`servers/qa-server`. The generator executes the actual service and retains PASS,
FAIL, UNTESTED and ERROR packets; no model invents the reference verdict.
