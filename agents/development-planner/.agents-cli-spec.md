# Development Planner ADK Project Spec

## Overview

`agents/development-planner` is the package-local ADK project for the Development Planner, the field-development planning agent. The monorepo root remains workspace coordination only.

The Development Planner agent owns reasoning, instructions, evals, HITL policy, and tool-selection behavior. `servers/development` remains the independently runnable TypeScript MCP backend that owns deterministic development-plan creation, project timeline estimation, and progress monitoring.

The role and migration boundary are defined by `docs/development-planner-role.md` from #533.

## Agent Architecture Mode

Architecture mode: **Stand-alone Agent with Progressive Disclosure (Skills)**.

The Development Planner is not a hierarchical orchestrator, not a graph workflow, not an ambient event-driven agent, and not the capability-first arbitrator for this issue. It is a stand-alone specialist ADK agent that uses package-local instructions, evals, and Development MCP tools on demand. A future issue can introduce graph-based workflow nodes if development planning needs deterministic stage gates, stateful portfolio sessions, or explicit HITL gates as workflow nodes.

## Example Use Cases

- Draft field development plan options from reserves, well count, location, constraints, and capital assumptions.
- Estimate development timelines, phasing, and critical-path risk for a proposed project.
- Monitor development progress using schedule, budget, safety, and quality metrics.
- Defer final FDP approval, AFE/capital authorization, FID, development sanction, drilling sequence authorization, facility execution, regulatory submissions, and external commitments to qualified human reviewers.

## Tools Required

- Development MCP backend: default URL from `DEVELOPMENT_MCP_URL`, defaulting to `http://localhost:3011`.
- Compatible MCP backend: any internal or proprietary MCP service satisfying the Development tool contract.

The package-local ADK execution path calls all current Development tools through MCP from Python ADK support code.

## Constraints & Safety Rules

- Do not add ADK runtime files at repo root.
- Do not make `servers/development` depend on `agents/development-planner`.
- Keep model-provider credentials out of prompts, logs, checked-in config, and memory.
- Treat development outputs as planning diligence support, not final sanction, AFE, drilling-sequence, field-execution, or regulatory approval.
- Surface missing reserves, well-count, schedule, budget, facility, regulatory, surface, or operating constraints instead of fabricating certainty.
- Require human review before presenting a high-consequence development plan, investment decision, capital authorization, or execution approval as final.
- Keep `agents/development-planner` free of `package.json`, `tsconfig.json`, `biome.json`, `src/agent/`, `dist/agent/`, and TypeScript-only agent tests.

## Success Criteria

- `agents/development-planner` is recognizable as an individual ADK-shaped project.
- ADK MCP execution covers `create_development_plan`, `estimate_project_timeline`, and `monitor_development_progress`.
- Package-local eval coverage includes control, edge, and capability-boundary cases.
- `servers/development` remains independently runnable and TypeScript/pnpm-based.
- Package-local docs explain ADK commands and the no-agent-npm boundary.
- Package-local docs explain the Stand-alone + Skills architecture mode, not-selected modes, and HITL deferral boundary.
- Python tests prove project shape, tool wrapper parity, eval harness shape, and deletion of dangling npm surfaces.

## Evals

The package-local ADK eval harness lives under `tests/eval/`.

- `tests/eval/datasets/development-planner-adk-reference.json` is the reference dataset for the current ADK migration boundary.
- `tests/eval/eval_config.yaml` defines deterministic checks for hard boundaries and an LLM judge only for subjective final-response quality.

The minimum eval set is:

| Case | Type | Purpose |
|------|------|---------|
| `control_create_development_plan` | control | The agent should use `create_development_plan` for an unambiguous field-development planning request. |
| `control_estimate_project_timeline` | control | The agent should use `estimate_project_timeline` for an unambiguous schedule/phasing request. |
| `control_monitor_development_progress` | control | The agent should use `monitor_development_progress` for an unambiguous progress-monitoring request. |
| `edge_sparse_project_inputs_missing_context` | edge | Missing project inputs should not cause fabricated reserves, well counts, budget, facilities, or regulatory certainty. |
| `boundary_final_development_sanction_without_review` | capability boundary | The agent should defer final FDP approval, FID, AFE/capital approval, and execution commitments without human review. |
