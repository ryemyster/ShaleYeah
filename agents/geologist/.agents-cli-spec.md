# Geologist ADK Project Spec

## Overview

`agents/geologist` is the package-local ADK project for Marcus Aurelius Geologicus, the geological diligence agent. The monorepo root remains workspace coordination only; ADK project shape lives inside this package.

The Geologist agent owns reasoning, instructions, evals, HITL policy, memory policy, and tool-selection behavior. `servers/geowiz` remains the independently runnable MCP backend that owns deterministic geology tools, file parsing, and domain processing.

## Agent Architecture Mode

Architecture mode: **Stand-alone Agent with Progressive Disclosure (Skills)**.

The Geologist is not a hierarchical orchestrator, not a graph workflow, not an ambient event-driven agent, and not the capability-first arbitrator for this issue. It is a stand-alone specialist ADK agent that uses package-local instructions, evals, and Geowiz MCP tools on demand. A future issue can introduce graph-based workflow nodes if geological review needs deterministic routing, stateful session control, or explicit HITL gates as workflow nodes.

## Example Use Cases

- Assess whether a LAS/well-log packet is sufficient for first-pass geologic diligence.
- Ask which Geowiz MCP tool should process a given geology artifact.
- Produce a formation-quality summary that cites required follow-up data.
- Explain when human review is required before saving or promoting a finding.

## Tools Required

- Geowiz MCP backend: default URL from `GEOWIZ_MCP_URL`, defaulting to `http://localhost:3001`.
- Compatible MCP backend: any internal or proprietary MCP service satisfying the Geowiz geology tool contract.

The package-local ADK execution path calls every current Geowiz tool through MCP from Python ADK support code. `save_finding` is exposed through an ADK `FunctionTool` confirmation gate so persistence remains reviewed.

## Constraints & Safety Rules

- Do not add `agents-cli-manifest.yaml`, `pyproject.toml`, `app/agent.py`, or ADK runtime files at repo root.
- Do not hardcode Google Agent Runtime, Cloud Run, GKE, Fly.io, or any other deployment target as mandatory.
- Do not make `servers/geowiz` depend on `agents/geologist`.
- Keep model-provider credentials out of prompts, logs, checked-in config, and memory.
- Require human approval for persistent finding saves, memory promotion, destructive actions, low-confidence recommendations, and missing critical data that would change an investment decision.

## Success Criteria

- `agents/geologist` is recognizable as an individual ADK-shaped project.
- ADK MCP execution covers all current Geowiz tools, with confirmation required for `save_finding`.
- Package-local eval coverage includes a control case, edge case, and capability-boundary case for the ADK prompt/tool path.
- Geowiz remains the default backend and remains independently runnable.
- Package-local docs explain ADK commands, the Stand-alone + Skills architecture mode, not-selected modes, and HITL deferral boundary.
- Python tests prove project shape, tool wrapper parity, eval harness shape, and deletion of dangling npm surfaces.

## Evals

The package-local ADK eval harness lives under `tests/eval/`.

- `tests/eval/datasets/geologist-adk-reference.json` is the reference dataset for the current ADK migration boundary.
- `tests/eval/eval_config.yaml` defines deterministic checks for hard boundaries and an LLM judge only for subjective final-response quality.
- `agents-cli eval run` runs ADK evals from this package when credentials are available.

The minimum eval set is:

| Case | Type | Purpose |
|------|------|---------|
| `control_analyze_formation` | control | The agent should use `analyze_geowiz_formation` for an unambiguous formation-analysis request. |
| `control_assess_las_quality` | control | The agent should use `assess_geowiz_quality` for an unambiguous LAS quality request. |
| `control_process_well_logs` | control | The agent should use `process_geowiz_well_logs` for an unambiguous well-log processing request. |
| `control_process_gis` | control | The agent should use `process_geowiz_gis` for an unambiguous GIS processing request. |
| `control_process_access_database` | control | The agent should use `process_geowiz_access_database` for an unambiguous Access DB request. |
| `control_process_document` | control | The agent should use `process_geowiz_document` for an unambiguous document extraction request. |
| `control_process_seismic_data` | control | The agent should use `process_geowiz_seismic_data` for an unambiguous seismic processing request. |
| `control_process_aries_database` | control | The agent should use `process_geowiz_aries_database` for an unambiguous ARIES reserves request. |
| `edge_sparse_history_missing_context` | edge | Sparse history and missing context should not cause fabricated geology findings. |
| `boundary_save_without_approval` | capability boundary | The agent should defer/escalate rather than save or promote a finding without approval. |
