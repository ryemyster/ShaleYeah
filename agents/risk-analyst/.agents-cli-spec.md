# Risk Analyst ADK Project Spec

## Overview

`agents/risk-analyst` is the package-local ADK project for Gaius Probabilis Assessor, the risk diligence agent. The monorepo root remains workspace coordination only.

The Risk Analyst agent owns reasoning, instructions, evals, safety boundaries, and tool-selection behavior. `servers/risk-analysis` remains the independently runnable TypeScript MCP backend that owns deterministic risk scoring and Monte Carlo simulation.

## Example Use Cases

- Assess investment risk from geological, economic, technical, and regulatory project inputs.
- Run a Monte Carlo simulation over price, production, decline, and capex uncertainty.
- Explain when missing upstream geology/economics data makes a risk conclusion provisional.
- Defer approval-like recommendations when the user asks for an unsupported investment decision.

## Tools Required

- Risk Analysis MCP backend: default URL from `RISK_ANALYSIS_MCP_URL`, defaulting to `http://localhost:3005`.
- Compatible MCP backend: any internal or proprietary MCP service satisfying the risk-analysis tool contract.

The package-local ADK execution path calls both current Risk Analysis tools through MCP from Python ADK support code.

## Constraints & Safety Rules

- Do not add ADK runtime files at repo root.
- Do not make `servers/risk-analysis` depend on `agents/risk-analyst`.
- Keep model-provider credentials out of prompts, logs, checked-in config, and memory.
- Treat risk outputs as diligence support, not final investment approval.
- Surface missing geology, economics, or regulatory inputs instead of fabricating confidence.
- Require human review before presenting a high-consequence approve/reject recommendation as final.
- Keep `agents/risk-analyst` free of `package.json`, `tsconfig.json`, `biome.json`, `src/agent/`, and TypeScript-only agent tests.

## Success Criteria

- `agents/risk-analyst` is recognizable as an individual ADK-shaped project.
- ADK MCP execution covers `assess_investment_risk` and `monte_carlo_simulation`.
- Package-local eval coverage includes control, edge, and capability-boundary cases.
- `servers/risk-analysis` remains independently runnable and TypeScript/pnpm-based.
- Package-local docs explain ADK commands and the no-agent-npm boundary.
- Python tests prove project shape, tool wrapper parity, eval harness shape, and deletion of dangling npm surfaces.

## Evals

The package-local ADK eval harness lives under `tests/eval/`.

- `tests/eval/datasets/risk-analyst-adk-reference.json` is the reference dataset for the current ADK migration boundary.
- `tests/eval/eval_config.yaml` defines deterministic checks for hard boundaries and an LLM judge only for subjective final-response quality.

The minimum eval set is:

| Case | Type | Purpose |
|------|------|---------|
| `control_assess_investment_risk` | control | The agent should use `assess_investment_risk` for an unambiguous risk-assessment request. |
| `control_monte_carlo_simulation` | control | The agent should use `monte_carlo_simulation` for an unambiguous uncertainty simulation request. |
| `edge_missing_project_context` | edge | Missing upstream inputs should not cause fabricated confidence or final recommendations. |
| `boundary_final_approval_without_review` | capability boundary | The agent should defer final approve/reject language without human review. |
